An environment supplies scoped actions and observations for a research question.
An instrument adapter is one building block. Meaningful research environments also
need domain-reviewed tasks, outcome measures and comparison conditions.

## Reference components

| Component | Native task | Observations |
| --- | --- | --- |
| PyLabRobot liquid handler | `inspect_labs/serial_dilution`, `inspect_labs/worklist_transfer` | Deck state, volumes, concentrations, tip usage and restricted-well events |
| Synthetic measurement service | `inspect_labs/measurement` | Job identity, state and recorded result |
| Synthetic report transfer | `inspect_labs/handoff` | Destination and delivered content identity |
| Robot bridge | `inspect_labs/robot_step` | Native Inspect Robots records and metrics |

The default liquid backend is simulated and assumes ideal mixing. Synthetic services
exercise software mechanics. A robot handoff can require a native readiness trial,
but it does not demonstrate physical sample transfer.

## Discover installed components

```bash
inspect-labs list
inspect-labs doctor --environment liquid-handler
```

`doctor` checks declarations and requirements without constructing providers or
touching hardware. It does not run lifecycle conformance or verify that an instrument
or external runtime works.

## Optional plugins

Install plugins from the checkout into the same Python environment:

```bash
uv pip install --python .venv/bin/python \
  ./plugins/inspect-labs-opentrons \
  ./plugins/inspect-labs-plate-reader \
  ./plugins/inspect-labs-commec
```

| Plugin | Provides | Current limits |
| --- | --- | --- |
| Opentrons | OT-2 backend declarations and a simulator | Simulator mechanics do not establish hardware compatibility |
| Plate reader | Native absorbance QC task through PyLabRobot's device-free reader API | Seeded synthetic values, no validated assay or physical reader |
| Common Mechanism | Bounded screening review with IBBIS Commec and a simulated disposition service | Fixture mechanics verified; full-reference runtime gate pending; no real order fulfillment |

Each plugin directory includes its own README, controls and tests. Scanner
recommendations are not biological ground truth or authorization. No IBBIS
affiliation is implied.

## Robot integration

```bash
uv pip install --python .venv/bin/python '.[robots]'
```

The extra installs a pinned Inspect Robots commit. Robot tasks use its registered
policies and embodiments. Physical embodiments require explicit identities for
supported native device slots and host authorization before construction. Default
guardrails remain native.

Physical backends are refused unless `allow_physical=True` is passed by the host.
That assertion does not provide facility authorization, interlocks or a validated
physical protocol. Device claims coordinate participating evaluations on one host.

## Publish a plugin

Packages register environments and backends using the Python entry-point groups
`inspect_labs.environments` and `inspect_labs.backends`. Declare runtime requirements,
device identities and computation, simulation or physical mode honestly. Existing
clients continue to own operational jobs, access control and cancellation.

The detailed source guides are `docs/adapters.md` and `docs/authoring.md` in the
checkout. [Authoring guide](/authoring) introduces the public binding protocol.
